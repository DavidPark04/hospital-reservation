# 프로젝트 계획서

기준일: 2026-11-20. [노션 서비스 기획과 범위](https://app.notion.com/p/879b8822a70f82f789298129ce73194d)에 첨부된 「AI 기반 병원 예약 지원 서비스 기획서」와 [주차별 계획](https://app.notion.com/p/050b8822a70f83c0bdcf81cbf0090447)을 반영합니다. 아래 일정과 완료 기준은 작업 계획이며 완료 실적이 아닙니다. 11/20 로컬 기능 통합과 Vercel 배포 결정 이후의 실제 상태는 [진행 현황](progress-and-next.md)을 따릅니다.

## 목표와 범위

AI 상담 또는 직접 검색으로 병원을 찾고, 저장된 가상 의료진·일정으로 모의 예약을 생성·변경·취소합니다. 실제 병원 정보와 가상 의료진·모의 예약을 화면에서 구분합니다. 2026-11-21 추가 요청으로 병원 상세의 카카오 지도 위치 표시와 외부 카카오맵 길찾기 연결을 포함합니다. 실제 병원 접수, 진단·처방, 결제, 실시간 대기열, 사이트 내부 경로 계산·내비게이션, 모바일 앱은 범위 밖입니다.

- 기말 전 필수: 회원가입·로그인·로그아웃, 병원 검색·상세, AI 조건 추출·추가 질문, 근거·출처·조회 시점 표시, 가상 의료진·일정, 본인 예약·변경·취소, 관리자 일정·정원·휴진 관리.
- 핵심 검증: 정원 초과·중복 요청·타인 예약 접근 방지, 취소 정원 복구 1회, 일정 변경 실패 시 롤백.
- 시험 이후 확장: 병원평가 정보, NMC 진료요일, 동의·보관 기간을 검토한 상담 이력, 이메일 알림, 전체 예약·회원 관리 도구.

영통구를 초기 검증 지역으로 제안하며 최종 범위는 팀에서 확정합니다. React·TypeScript·Vite·TanStack Query, Spring Boot 3·Java 21·Security·Data MongoDB·WebClient, MongoDB Atlas를 기준으로 합니다. 초기에는 FE Vercel·BE Render 후보를 검토했으나, 11/20 사용자 결정으로 Vercel의 FE·Java Container BE 구성으로 변경했습니다. 11/21에는 김도형 소유의 Vercel 프로젝트와 [hospital-reservation-app.vercel.app](https://hospital-reservation-app.vercel.app)으로 운영 대상을 옮기고, 기존 GitHub 저장소의 `main` 검사 성공 후 자동 배포하도록 구성했습니다.

## 역할과 점검

박다윗(DavidPark04)·김도형(kdh0381)의 상세 FE/BE 담당은 아직 미정입니다. Issue마다 담당자 1명을 정하고 API·DB 변경 내용과 검증 결과를 공유합니다. 필요하면 상대에게 리뷰를 요청하며, 승인은 병합 필수 조건이 아닙니다.

노션의 6회 점검 계획은 범위(11/20~22), API·DB·인증(11/25), 예약(11/29), AI·사용자 흐름(12/2), 배포·정합성(12/5), 보고서·시연(12/8)입니다. 예정 안건이며 실제 개최 시간·참석자·결정은 회의 후 기록합니다.

## 확인된 근거와 남은 검증

기준 기획서에는 로컬 MongoDB replica set PoC 10개 시나리오 통과가 기재되어 있습니다. 이 저장소에서 Spring 서비스·Atlas·실제 인증 API 연동이 검증되었다는 뜻은 아닙니다. 해당 검증과 증거 등록은 구현 작업에 포함합니다. Vercel Container/Services의 실제 배포·사용량·유휴 후 시작 지연도 확인이 필요합니다.

팀이 확정한 노션 결정과 기준 기획서를 저장소 문서·코드에 함께 반영합니다. 차이가 생기면 관련 Issue와 PR에 근거를 남깁니다.
