# 시연 시나리오 초안

12/5 통합 검증 결과를 반영하고 12/7~8에 리허설합니다. 12/8까지 준비를 마치며 실제 사용자 데이터 대신 가상 계정·샘플 일정을 사용합니다. 아래는 계획이며 구현 완료 후 검증된 동작으로 갱신합니다.

1. 서비스 목적과 모의 예약임을 설명합니다.
2. 직접 검색으로 지역·진료과를 선택하고 실제 자료의 출처를 확인합니다.
3. AI 상담으로 조건을 정리하고, 조회된 병원 후보와 근거를 확인합니다.
4. 샘플 의료진·일정 선택 → 로그인 → 최종 확인 → 모의 예약을 진행합니다.
5. 내 예약 조회·변경·취소와 관리자 일정·정원·휴진 관리를 보여 줍니다.
6. 예약 동시 요청·동일 키 재시도·다른 본문 충돌·타인 예약 접근·변경 실패 롤백의 테스트 결과를 제시합니다.
7. AI 실패 시 직접 검색, 병원 API 실패 시 캐시와 확인일 또는 재시도 안내를 확인합니다.
8. 실제 연동·미연동 범위와 시험 이후 확장 기능을 구분해 설명합니다. 로컬 MongoDB PoC와 Spring·Atlas 통합 검증 결과를 구분합니다.
