# 대화형 병원 추천

증상·진료 목적을 대화로 확인하고, 주변 병·의원 탐색과 세부 분야 전문 진료기관 탐색을 연결합니다. 진단, 치료 성적 보장, 실제 병원 예약은 제공하지 않습니다. 의료진과 예약 시간표는 기존과 같이 모의 자료입니다.

## 대화 흐름

1. 현재 불편한 점, 시작 시점과 변화, 기존 진단·의뢰 여부, 진료 목적을 필요한 만큼 질문합니다. 사용자가 말하지 않은 사실이나 이전 AI 답변을 환자 정보로 확정하지 않습니다.
2. 일반적인 첫 진료·관리 목적에는 가까운 병·의원 또는 전문병원·대학병원 중 원하는 방향을 묻습니다. 전문검사·수술 상담·진료 의뢰 등의 목적에는 전문 진료기관 탐색을 안내합니다.
3. 증상이 지속되거나 악화됐다는 말에는 진료를 미루지 않도록 안내합니다. 심하다는 표현만으로 비응급이라고 확정하지 않으며, 응급이 의심되는 경우 병원 추천보다 즉시 도움을 요청하도록 안내합니다.
4. 지역 또는 사용자가 명시적으로 제공한 위치를 확인한 뒤 병원을 찾습니다. 전문 진료기관은 전국 검색을 선택할 수 있습니다. 추가 질문의 선택지는 일반 사용자 메시지로 전송하므로 자유 입력과 같은 대화 흐름을 이용합니다.

특정 분야 병원 정보를 찾는 일반 질문에는 개인 증상이나 진단을 반드시 입력할 필요가 없습니다. 내분비내과·소화기내과·정형외과의 세부 분야 등은 `specialty`라는 검색 조건으로 다룹니다. 공공데이터의 일반 진료과 소속과 세부 전문성 근거를 구분합니다.

## 주변 병·의원

`hospitals`의 활성 여부·진료과 소속·병원 종별·주소·좌표를 사용합니다. 기본 병원 API를 다시 호출하거나 모든 병원의 상세 정보를 적재하지 않습니다.

- 기준 위치를 제공하면 주변 약 30km 범위에서 직선거리를 비교합니다. 이동 거리나 이동 시간으로 표시하지 않습니다.
- 위치 없이 지역을 입력하면 지역과 진료과가 일치하는 병·의원을 안내합니다. 정확한 거리순이라고 표시하지 않습니다.
- 실제 진료시간·대기시간·접수 가능 여부는 현재 자료로 확인하지 않습니다. 모의 예약 시간표를 실제 영업시간으로 사용하지 않습니다.

## 전문 진료기관과 웹 근거

GPT-6.2 Sol의 Responses API 웹 검색 도구로 짧은 진료 분야와 희망 지역에 관한 공개 자료를 확인합니다. 개인 대화 원문, 계정 정보, 정밀 좌표는 웹 검색 질의에 보내지 않습니다. 검색된 기관명·분원·도로명 주소를 DB와 대조하고, 확실히 연결된 기관의 기존 ID를 사용합니다.

모델 응답에 실제 웹 검색 실행과 출처 인용이 있는지 확인합니다. 특정 사이트 허용 목록으로 제한하지 않고 검색으로 접근 가능한 공개 웹 자료 전반을 참고합니다. 공식 안내, 기사, 블로그, 인스타그램 등 SNS는 그 예입니다. 출처 링크마다 `병원·공공자료`, `기사·보도`, `후기·SNS`, `웹 참고` 유형을 표시합니다. 자료는 검색 결과의 AI 요약이며, 서버가 각 원문을 직접 검증했다는 뜻은 아닙니다. 개인 후기의 경험·언급을 의료적 우수성으로 바꾸지 않습니다.

검색 결과의 병원명·분원과 도로명·번지는 DB와 대조합니다. 모호한 주소, DB에 없는 기관, 실제 검색 인용이 없는 출처는 자동으로 연결하지 않습니다. 참고 자료를 찾지 못하면 확인 실패와 재검색 방법을 안내하며 임의의 유명 병원 목록으로 대체하지 않습니다.

센터·전문 진료 프로그램 안내와 공개 후기는 치료 성적이나 병원 간 우열의 증거와 다릅니다. 과별로 하나의 최고 병원을 고정하지 않고 검색된 진료 분야와 출처를 표시합니다. 병원별 추천 카드에 참고 링크와 검색 시각을 제공합니다.

## 저장·비용·장애 처리

`hospitalRecommendationEvidence`는 진료 분야·지역별 공개 검색 결과를 24시간 재사용합니다. 계정과 연결되지 않으며 증상 원문·정밀 위치를 저장하지 않습니다. 유효한 결과가 없는 검색이나 외부 호출 실패는 성공 결과로 저장하지 않습니다. 캐시 사용 시 외부 검색을 반복하거나 확인 시각을 새 시각으로 덮어쓰지 않습니다.

웹 검색은 모델 토큰 외에 도구 호출 비용이 발생할 수 있습니다. 일반 진료 대화와 주변 병·의원 조회에는 웹 검색을 사용하지 않고, 전문 진료기관 탐색에만 호출을 제한합니다. AI 실패 시 진료 필요성을 임의로 판단하지 않고 추가 확인 또는 직접 검색을 안내합니다.

## 대화 한도와 오류 복구

대화는 최대 20개 메시지·9000자까지 전송하며 화면에서 한도 도달 전에 새 상담을 안내합니다. 이전 증상 맥락을 조용히 버리고 추천을 계속하지 않습니다. 서버 연결 실패, 응답 지연, 요청 횟수 제한은 구분해 안내하고 같은 요청의 재시도 또는 새 상담을 지원합니다.

로컬 실행 스크립트는 완성된 backend JAR을 `.runtime`의 고유 실행본으로 복사합니다. 다음 빌드가 원본 JAR을 바꿔도 기존 서버가 읽는 파일은 유지됩니다. 새 코드를 실행하려면 기존 서버를 종료한 후 다시 시작하며, 종료 시 해당 실행본만 정리합니다.
